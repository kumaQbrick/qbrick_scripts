# 引き継ぎ手順

脚本棚を次の代に渡すときと、管理者が日ごろやることをまとめています。
「誰がどのアカウントを持っているか」が分からなくなると、サイトは止まってしまいます。このファイルを毎年更新してください。

---

## 管理しているもの

| もの | どこで管理するか | 持ち主にしておくもの |
|---|---|---|
| サイトのコード | GitHub リポジトリ | サークルの GitHub Organization（またはサークル用アカウント） |
| データ・ログイン・PDF | Supabase プロジェクト | サークル用アカウントの Supabase Organization |
| サイト内の管理者 | 脚本棚の「管理」ページ | 現役の管理者（2人以上が安心） |
| 招待コード | 脚本棚の「管理」ページ | 管理者だけが知る |
| Secret key | Supabase の Project Settings > API Keys | 管理者のパソコンの `tools/.env` だけ |
| バックアップ | 管理者の手元（共有ドライブなど） | 管理者だけが見られる場所 |

## 代替わりのとき

### 1. 新しい管理者をサイトの管理者にする

1. 新しい管理者に、サイトでアカウントを作ってもらう（招待コードを渡す）
2. 「管理」ページのユーザー一覧で、その人の「管理者」にチェックを入れる
3. 新しい管理者がログインし直して「管理」メニューが出ることを確認する
4. 旧管理者の「管理者」チェックを外す（管理者が1人しかいないときは外せないようになっています）

### 2. Supabase を引き継ぐ

1. Supabase のダッシュボードで **Organization の Team** に新しい管理者を Owner として招待する
   - サークル用アカウントで運用しているなら、そのログイン情報を渡すだけでもかまいません
2. 旧管理者が手元に Secret key を持っていた場合は、**Project Settings > API Keys で Secret key を作り直し**、古い鍵を無効にする
3. Authentication の設定（Site URL、Redirect URLs、メール設定）が今のサイトのURLと合っているか確認する

### 3. GitHub を引き継ぐ

1. リポジトリ（または Organization）に新しい管理者を Owner / Admin として追加する
2. Settings > Pages が有効のままか確認する

### 4. 招待コードを変える

「管理」ページで新しい招待コードにします。変えても、すでにメンバーの人はそのままです。
卒業生がメンバーのままでいてよいかはサークルで決めてください。外すときは「管理」ページでメンバーのチェックを外します。

### 5. バックアップを取って、この表を更新する

## 日ごろやること

### 学期に1回くらい：バックアップ

Supabase の無料プランには自動バックアップがありません。

```bash
cp tools/.env.example tools/.env   # 初回だけ。URL と Secret key を書く
python3 tools/backup.py            # backups/日付時刻/ に保存される
```

- 中身：全テーブルの JSON、ユーザー一覧（メールアドレス）、すべての PDF、`summary.json`
- `summary.json` の `unreferenced_pdfs` は、どの脚本にも使われていない PDF（投稿の途中で失敗したものなど）の一覧です。気になるときは Supabase の Storage 画面から削除できます
- 招待コードやメールアドレス、未発表の脚本が入っているので、**GitHub には上げず**、管理者だけが見られる場所に保管してください（`backups/` は .gitignore 済み）

### サイトが動かないとき

| 症状 | よくある原因 | 対処 |
|---|---|---|
| 一覧が読み込めない・ログインできない | 1週間アクセスがなくて Supabase が一時停止した | Supabase のダッシュボードでプロジェクトを再開する |
| 「セットアップが必要です」と出る | `js/config.js` が初期値のまま | Project URL と Publishable key を書く |
| 確認メールが届かない | 標準のメール送信の上限 | README の「確認メールについて」を参照 |
| ログイン後に変なページへ飛ぶ・リンクが使えない | Site URL / Redirect URLs がサイトのURLと違う | Authentication > URL Configuration を直す |
| PDF が表示されない | 古いブラウザ・PDF が壊れている | 「新しいタブで開く」で読めるか確認。読めなければ投稿者に再アップロードを頼む |

### 容量を確認する

Supabase のダッシュボードの **Usage** で、ファイル保存（無料は 1GB）とデータベース（無料は 500MB）の使用量が見られます。
PDF 1本が 1MB 前後なら、900本くらいまでは無料の範囲に収まる計算です。足りなくなったら、古い脚本の PDF を圧縮して差し替えるか、有料プランを検討してください。

## 退会・削除の扱い

- 退会したい人のアカウントは、Supabase の **Authentication > Users** から削除します
- アカウントを削除しても、その人が投稿した**脚本は残ります**（サークルの記録として）。本人が脚本も消したいときは、先に本人が削除するか、管理者が詳細ページから削除してください
- 名前つきコメントは「退会したユーザー」として残り、いいねは消えます

## データベースを作り直すとき

`supabase/schema.sql` は新しいプロジェクトに1回だけ流す前提です。
別のプロジェクトへ引っ越す場合、脚本と PDF はバックアップから戻せますが、パスワードは移せないので、メンバーには新しいサイトで登録し直してもらう必要があります。
