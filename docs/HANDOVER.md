## 代替わり

1. 次の人にサイトで登録してもらい、管理ページで「管理者」にチェック
2. Supabase: Organization の Team に Owner で招待（またはプロジェクトごと移す）。前の人が secret key を持っていたら API Keys で作り直す
3. GitHub: リポジトリを移すか、Admin で招待。リポジトリ名や持ち主が変わるとサイトのURLも変わるので、Supabase の Site URL / Redirect URLs も直す
4. 招待コードを変える（今のメンバーはそのまま）。卒業生を外すかはサークルで決める
5. 自分の管理者チェックを外す（管理者が1人だけのときは外せない）
6. バックアップを取って、上の表を更新

## バックアップ（学期に1回くらい）

Supabase の無料プランには自動バックアップがない。

```
cp tools/.env.example tools/.env   # 初回だけ。secret key を書く
python3 tools/backup.py
```

`backups/日時/` に全テーブルの JSON、ユーザー一覧、PDF が入る。招待コードやメールアドレスも入っているので、GitHub には上げない（.gitignore 済み）。
`summary.json` の `unreferenced_pdfs` はどの脚本にも使われていない PDF。気になれば Supabase の Storage から消す。

## 動かないとき

| 症状 | だいたいの原因 |
|---|---|
| 何も読み込めない | 1週間アクセスがなくて Supabase が止まった → ダッシュボードで Restore |
| 確認メールが来ない | 標準のメール送信の上限。README の「確認メールについて」 |
| メールのリンクで変な所に飛ぶ | Site URL / Redirect URLs がサイトのURLと違う |
| PDF が出ない | 「別タブで開く」で読めるか確認。だめなら投稿者に上げ直してもらう |
| 古い画面のまま | ブラウザのキャッシュ。Ctrl+Shift+R |

## 仕組みのメモ

### 誰が何をできるか

| | 公開の脚本を読む | メンバー限定を読む | 投稿・いいね・コメント | 他人の脚本・コメントを消す | 匿名の中身を見る |
|---|---|---|---|---|---|
| 未ログイン | ○ | | | | |
| ログインのみ | ○ | | | | |
| メンバー | ○ | ○ | ○ | | |
| 管理者 | ○ | ○ | ○ | ○ | ○ |

画面で隠しているだけではなく、DB の RLS で止めている。publishable key で直接 API を叩かれても、これ以上のことはできない。

### 匿名コメントといいね

- 匿名コメントは `comments.author_id` を空にして、本当の投稿者は `comment_authors` に入れる。読めるのは本人と管理者だけ。このことはコメント欄とルールページに書いてある（書いておくこと自体が大事なので消さない）
- いいねは誰が押したかを画面に出さない。管理ページにも出していない。ただし Supabase のダッシュボードを見られる人は見える

### 決めたことの理由

- ログインのリンクは implicit フロー: pkce だと、メールのリンクを別のブラウザ（スマホのメールアプリ内など）で開いたときにログインできない
- pdf.js は legacy ビルド: 通常版は少し古いブラウザで PDF を描けなかった
- ライブラリは `vendor/` に同梱: CDN が止まったり変わったりしても動くように
- アカウントを消しても脚本は残す: サークルの記録として

### 無料プランの上限（2026年10月時点の公式料金ページ。変わることがある）

- 1週間アクセスがないと一時停止
- ファイル 1GB（1ファイル 50MB。このサイトでは 20MB に制限）、DB 500MB
- Usage 画面で使用量が見られる。PDF が1本 1MB 前後なら 900本くらいまで入る

### できないこと

コメントの編集、通知、PDF の版の履歴（差し替えると前のは消える）、PDF の中身の検索。
