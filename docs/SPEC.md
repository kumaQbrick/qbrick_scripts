# 脚本棚 仕様書

## 目的

映画の脚本を募集して1本に決まると、ほかの脚本はそのまま使われなくなってしまう。
採用されなかった脚本も含めて残し、読まれたり、次の作品に使われたりする場所をつくる。

## 利用者と権限

| | 読む（公開の脚本） | 読む（メンバー限定） | 投稿 | いいね | コメント | 他人の脚本・コメントの削除 | 匿名コメントの投稿者を見る |
|---|---|---|---|---|---|---|---|
| ログインしていない人 | ○ | × | × | × | × | × | × |
| ログインしたがメンバーでない人 | ○ | × | × | × | × | × | × |
| メンバー | ○ | ○ | ○ | ○（自分の脚本以外） | ○ | × | × |
| 管理者 | ○ | ○ | ○ | ○ | ○ | ○ | ○ |

- メンバーになるには、登録時（またはアカウント画面）で招待コードを入力する
- 管理者は管理ページでメンバー・管理者の付け外しと招待コードの変更ができる
- これらの制限は画面ではなく**データベースの権限ルール（RLS）で強制**している。Publishable key を使って直接 API を呼ばれても、ルール以上のことはできない

## 画面

| URL | 画面 | 内容 |
|---|---|---|
| `#/` | 一覧 | 台本の表紙（縦書き・右綴じ）を並べる。キーワード検索（タイトル・筆者名・あらすじ）、ジャンル・長さ・状態・使用許可での絞り込み、並び替え（新しい順・更新順・いいね順・コメント順・タイトル順）、自分の投稿／いいねした脚本だけ表示。条件は URL に入るので共有できる |
| `#/s/<id>` | 詳細 | 情報、いいね、PDF の表示（pdf.js でページごとに描画）、新しいタブで開く・ダウンロード、コメント |
| `#/new`, `#/edit/<id>` | 投稿・編集 | タイトル、筆者名、あらすじ、ジャンル（最大3）、長さ、想定上映時間、状態、使用許可、公開範囲、PDF |
| `#/login`, `#/signup`, `#/reset`, `#/new-password` | ログイン関連 | 登録時に表示名と招待コードを入力 |
| `#/account` | アカウント | 招待コード入力、表示名・パスワード変更、ログアウト |
| `#/admin` | 管理 | 招待コード、ユーザー一覧（メール付き）、最近のコメント（匿名の投稿者付き） |
| `#/about` | 使い方とルール | 公開範囲、匿名の仕組み、使用許可の意味 |

画面の切り替えは URL の `#` 以降で行う（GitHub Pages ではサーバー側で URL を振り分けられないため）。

## 脚本の項目

| 項目 | 値 | 備考 |
|---|---|---|
| タイトル | 1〜100文字 | |
| 筆者名 | 1〜50文字 | アカウントの表示名とは別。ペンネーム・共作者名も書ける |
| あらすじ | 0〜2000文字 | |
| ジャンル | 1〜3個 | 選択肢は `js/config.js` |
| 長さ | 短編 / 中編 / 長編 | 目安の分数は `js/config.js`（サークルで決める） |
| 想定上映時間 | 1〜600分（任意） | |
| 状態 | 検討中 / 未採用 / 採用・制作中 / 完成 | 制作中・完成は表紙に判子が付く |
| 使用許可 | 自由に使ってOK / 使う前に筆者に相談 / 読むだけ | |
| 公開範囲 | メンバーだけ（既定） / リンクを知っている人なら誰でも | |
| PDF | 20MB まで | Storage の非公開バケットに保存 |

## データベース（`supabase/schema.sql`）

| テーブル | 内容 | 読める人 |
|---|---|---|
| `profiles` | 表示名、メンバー・管理者フラグ | 誰でも（表示名を出すため） |
| `scripts` | 脚本。いいね数・コメント数もここに持つ | 公開範囲のとおり |
| `likes` | いいね（脚本×ユーザーで一意） | **本人の行だけ**。数は `scripts.like_count` で公開 |
| `comments` | コメント。匿名のときは `author_id` が空 | その脚本を読める人 |
| `comment_authors` | コメントの本当の投稿者 | **本人と管理者だけ** |
| `app_secrets` | 招待コード | 誰も読めない（関数経由で管理者だけ） |

主な関数（画面から呼ぶもの）

- `post_comment(脚本ID, 本文, 匿名か)`：コメントと本当の投稿者を同時に記録する。コメントの直接の書き込みは禁止
- `redeem_invite(コード)`：正しければメンバーにする
- `admin_list_users()`, `admin_set_member()`, `admin_set_admin()`, `admin_get_invite_code()`, `admin_set_invite_code()`：管理者専用（関数の中で管理者か確認する）

その他の決まり

- いいね数・コメント数はトリガーで数え直す。利用者はこの列を書き換えられない（列単位で権限を制限）
- `updated_at` は内容が変わったときだけ更新（いいねされても変わらない）
- 管理者は最後の1人を外せない
- 招待コードは8文字以上

### PDF の保存

- バケット `scripts`（非公開、PDF のみ、20MB まで）
- 置き場所：`<投稿者のユーザーID>/<ランダムなID>.pdf`。自分のフォルダにしかアップロードできない
- 読めるのは「その PDF を使っている脚本を読める人」。閲覧・ダウンロードは**1時間で切れる署名つきURL**を使う
- 脚本を削除・PDF を差し替えたとき、古い PDF は画面側で削除する。失敗して残ったファイルはバックアップスクリプトが一覧にする

## 匿名といいねの扱い（利用者への説明と一致させること）

- 匿名コメント：ほかの利用者には投稿者が分からない。管理者には分かる。このことはコメント欄と「使い方とルール」に明記している
- いいね：誰が押したかは画面に出さない（管理画面にも出さない）。データベースの管理者（Supabase のダッシュボードを見られる人）は技術的には確認できる

## 決めたことと、その理由

- **ログインは Supabase Auth のメール＋パスワード**：サークル内の利用で十分。Google ログインなども Supabase の設定で追加はできる
- **メール認証のリンクは implicit フロー**：スマホのメールアプリから開いた別のブラウザでもログインが完了するように
- **ライブラリは `vendor/` に同梱**：外部の配信サービスが止まったり仕様が変わったりしても、サイトが動き続けるように
- **pdf.js は legacy ビルド**：通常ビルドは新しい JavaScript の機能を使っていて、少し古いブラウザ（スマホを含む）で PDF が描けないことを確認したため
- **アカウントを消しても脚本は残す**：サークルの記録として残すため

## できないこと・今後の候補

- コメントの編集（削除して書き直す）
- 通知（新しい脚本・コメントのお知らせ）
- 脚本の版の履歴（PDF を差し替えると前の版は消える）
- 全文検索（PDF の中身は検索できない。あらすじは検索対象）
- 招待コードの総当たり対策は文字数だけ（8文字以上）。心配なら長めのコードにする

## 補足

- 登録時に入力した招待コードは、Supabase Auth のユーザー情報（user_metadata）にも残る。本人と、ダッシュボードを見られる人には見える
- 検索エンジン除けは `<meta name="robots" content="noindex">` のみ。URL を知っている人は「公開」の脚本を読めるので、未発表の作品は「メンバーだけ」にする
